# tools

`tools/` 保存和运行时代码解耦的辅助工具：采集、标注、训练、评估、诊断脚本都优先放在这里。

## 当前状态

- 当前默认运行目标是 bear。
- 低速跟随已经顺滑。
- 高速跟随仍然存在跟不上，需要继续采集高速场景数据和联合日志。
- 这里的工具不直接替代 `ros2_ws/` 里的 ROS2 节点，也不替代 `firmware/stm32_gimbal_control/` 里的下位机固件。

## 当前结构

- `dbus_diag_reader.py`：DBUS 诊断读取工具。
- `capture/`：数据采集工具骨架。
- `labeling/`：标注流程约定。
- `training/`：训练流程和模型导出工具。
- `evaluation/`：评估和对比工具。

## 高速跟随后续工具方向

建议后续优先补这些工具：

1. 同步记录 `/bear_detection/targets`、桥接发送坐标和 STM32 诊断帧的日志脚本。
2. 高速横移场景的离线评估脚本，统计丢检、中心点跳变、延迟和误差峰值。
3. 数据 manifest 扩展字段，记录速度、光照、运动模糊、遮挡和是否跟不上。

## 开发原则

- 工具要小而明确。
- 新目录使用无空格、全小写、下划线风格。
- 与数据、模型相关的工具优先落在 `tools/`，不要塞回历史工作区。
- 如果工具改变了采集、训练、评估流程，需要同步更新最近的 README。
